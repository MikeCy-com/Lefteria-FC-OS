# Persistent public news URL registry (foundation only)

SEO-02 / issue #446. Existing published news routes still use their current legacy title-plus-ID URLs. This migration introduces owner-only reservations; no backfill, route change, public resolver, admin editor, or new grant is activated.

- One globally unique ASCII slug reservation maps to one exact existing imported public news edition (organization plus immutable article ID). A canonical pointer is constrained to an alias of the same edition. Shared news can have distinct editions.
- Owner-only invoker function validates syntax, reserved route names, readiness, exact published document ownership and legacy raw-ID conflicts. Claims serialize and require the expected nonnegative monotonic revision (0 for initial claim). Each actual rename increments the revision, including restoration of a historical alias; same-slug requests with the correct revision are no-ops. Stale requests remain stale after a rename-and-restore cycle. Rename retains old reservations; another edition cannot acquire them. A prior alias may become canonical again for the same edition.
- Future document inserts and identity updates cannot shadow any reserved alias. Claims and relevant document writes use the existing READ COMMITTED owner workflow and conflicting document table locks; stronger transaction isolation is rejected for these operations rather than trusting a stale snapshot. Existing non-news writes and ordinary news content edits are unaffected. The import tool's initial-snapshot and replay rules remain unchanged.
- No anonymous/app/admin runtime role is granted table or function access. RLS without policies adds defense in depth. No public metadata or private source data is copied.
- Down refuses deletion when reservations exist. Sequential tests run in rollback-only disposable DB transactions; two independent committed fixture claims test cross-owner concurrency and clean up their random reservation. Both runtime roles are checked for direct table and function denial.

Remaining: explicit reviewed slug allocation/transliteration and collision suffix policy; inventory existing raw IDs and aliases, concurrent import-versus-claim verification, native draft publication integration, authorized per-organization editor with audit and compare-and-swap, read-only verified-public resolver, noindex for private/youth content, legacy 301s to ID-free routes, sitemap and canonical integration, concurrent rename and real admin permission tests, staging migration/rollback rehearsal. Do not populate the registry or switch URLs before these gates pass. This is not a completed clean URL feature.
