## Rules that apply to every sub-phase

- Native stack only (SvelteKit + TypeScript, ASP.NET Core .NET 10, PostgreSQL 18); contract-first: `contracts/openapi.json` changes with each endpoint.
- Dynamic permission contract: the UI renders from the backend's session payload (roles, capabilities, organization grants, module flags); nav items, tabs, buttons and fields appear/disappear when the backend changes them, without a redeploy. The server re-checks every permission on every request; the UI never is the gate. Original visibility rules per screen are in `ui-matrix.json` (`visibility`).
- Providers are built but OFF until keys are added (Twilio SMS, Payabl/Stripe checkout, WebPush/VAPID, social publishing, AI). Disabled providers return the existing safe unavailable state.
- Each sub-phase ends with: matrix rows flipped to `ported` only with contract + test evidence, visual-baseline rerun for touched routes, policy checks, unit/integration tests.
